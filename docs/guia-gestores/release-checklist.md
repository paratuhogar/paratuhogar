# Actualización de la guía

1. Identificar qué pantallas o funciones visibles cambiaron y qué páginas de la guía afectan. Revisar especialmente pedidos con poca conexión, estados, selección y descarga, comisiones, ranking y permisos de herramientas.
2. Partir del texto final aprobado en `contenido-final.json`. Actualizar instrucciones con los nombres de controles actuales y explicar qué significa cada confirmación. Mantener la diferencia entre guardar en el teléfono, enviar y recibir un pedido.
3. Capturar la interfaz real desde una sesión autorizada. Usar vistas públicas o datos de demostración claramente rotulados. Ocultar clientes, teléfonos privados, direcciones, credenciales, saldos reales e incidencias privadas. Conservar las leyendas de privacidad y los recortes identificados en el inventario. No inventar controles ni sustituir iconos por dibujos.
4. Registrar para cada nueva captura la página, función, rol, fecha, versión de código, dimensiones y SHA-256. Actualizar el inventario con la procedencia real. No dar por actualizadas imágenes de funciones que no se revisaron.
5. Preparar una versión para revisión en `docs/guia-gestores/build/`. Revisar todas las páginas renderizadas, texto, recortes, orden de lectura y enlaces; comprobar legibilidad móvil, controles reales y ausencia de datos privados. Obtener la aprobación correspondiente de la versión final.
6. Incorporar los bytes exactos del archivo aprobado en `guias/guia-gestores.pdf`; mantener esa ruta estable. El archivo debe pesar como máximo 5000000 bytes. Actualizar `guias/gestores.json` con `published: true`, `status: final`, fecha, revisión, bytes y SHA-256 reales. Registrar también la procedencia en `final-library-source.json`.
7. Recuperar el texto y las imágenes del nuevo archivo aprobado con `scripts/extract-guide-source.py`; revisar y actualizar `contenido-final.json` e `inventario-final-capturas.json`. Conservar el documento original editable si está disponible; la extracción no reemplaza esa fuente original.
8. Ejecutar `npm run check:guide`, `node --test tests/guide-release.test.cjs`, `PTH_GUIDE_TEST_PDF=guias/guia-gestores.pdf node tests/guide-download-browser.cjs`, `node tests/work-welcome-browser.cjs`, `node tests/announcement-browser.cjs`, `node tests/startup-browser.cjs`, `npm run check:js` y `git diff --check`. Chromium y un servidor local deben tener autorización del entorno. Verificar una sola tarjeta dentro del Dashboard, ninguna carga de guía en el Catálogo, cierre y reapertura de bienvenida, ausencia de diálogos simultáneos, desbordamiento móvil y exposición de la sesión anterior.
9. Publicar PDF, manifiesto, tarjeta y fuentes en una misma entrega. Confirmar el commit remoto. Comprobar la URL pública y la descarga únicamente mediante accesos autorizados disponibles; si HTTP está bloqueado, registrar ese límite sin afirmar que la comprobación se realizó.
10. Conservar el commit anterior para revertir la entrega completa. Si aparece un fallo, distinguir un problema de descarga, contenido o navegación antes de publicar otra revisión.
